# bipe-web: agent notes

Static site for bipe.chat. Vite + React 19 + TypeScript, prerendered to HTML; only `data-island` elements hydrate. Plain CSS on bipe-tokens (no Tailwind). See `../bipe/docs/website.md`.

## Commands

- `pnpm build`: typecheck, then `scripts/build.mjs` writes `dist/` (pages, `.md` twins, `llms.txt`, sitemap, icons).
- `pnpm preview`: serves `dist/` on port 4321.
- `pnpm store:images --device <iphone69|ipad13|play-phone|play-feature> [--locale pt-BR]`: renders the App Store and Play panels (`scripts/store-images.mjs`, bipe#455) from the `## Screenshots` tables in `../bipe-shared/product/appstore.md` (`title`, `sub`) and the captures in `../bipe-ios/appstore/raw/<device>/<appearance>/<locale>/`. Each panel has a centred title, one subtitle sentence and one upright iPhone (status bar and Dynamic Island drawn by `scripts/lib/panels.mjs`) at the same size and place. Sizes come from `../bipe-ios/appstore/devices.mjs`. Output: `../bipe-ios/appstore/screenshots/<device>/<locale>/` (committed there, the upload input) or `../bipe-android/appstore/screenshots/`. It stops on a missing, blank or wrong-size capture. `pnpm build` renders the store and Instagram sets (`scripts/brand-images.mjs`) into `.brand-images/` and `/sobre/marca/` (`/en/about/brand/`) lists them from their manifests, next to the logo and the link-preview cards. CI checks out `appstore/` of bipe-ios for the captures; commit new captures there. Change the panel text in `appstore.md`, never in the builder.
- `pnpm run deploy` (not `pnpm deploy`, which is a pnpm built-in): needs `scripts/deploy.env` (git-ignored, from `deploy.env.example`). Build, then `scripts/deploy.sh` copies `dist/` into `../bipe-infra/compose/site/` and rsyncs it to the dev node. No `--delete`.

## Rules

- pt-BR is the default at `/`. English is secondary under `/en/`. Never redirect by browser language.
- `/lgpd/` (`/en/lgpd/`) is Markdown built from `../bipe-shared/product/data.json` by `lgpdMarkdown` in `src/pages/LegalPage.tsx` (ADR 0090). Change the data there, never in the page. When the privacy policy changes a fact, change the register in the same commit.
- `/quem-pode-ler/` (`/en/who-can-read/`) and the summary on the e2ee feature page and the `no-ads` tentpole come from `../bipe-shared/product/privacy.json` through `src/pages/PrivacyPage.tsx` (ADR 0109). Change the facts there, never in the page.
- Privacy and terms text is `src/legal/*.md` (pt is the reference text). Docs text is `src/docs/<lang>/*.md`, listed in `src/pages/DocsPage.tsx`. Both render through `src/components/markdown.tsx`, which knows only `#` to `###`, `_meta_` lines, `- ` lists, `|` tables, ``` blocks, paragraphs, bold, `code` and links. The `.md` file is the page's Markdown twin as is.
- `/docs/` (`/en/docs/`) explains how Bipe works, for people and agents: domains (ADR 0062), architecture, links and the public API. `llms.txt` lists the docs first. When a host, a link format, a public API call or a stack part changes, change the docs page in the same commit. Docs state only what runs today: no roadmap, no hosting provider names, no IP addresses, no internal paths.
- Product copy, feature status and download links come only from `../bipe-shared/product/`. Do not write feature copy in a page. Chrome copy (nav, labels) is in `src/copy.ts`.
- UI strings in simulations come from `../bipe-shared/strings/` through `t()`. Scam, handle and name results come from the reference logic in `../bipe-shared/tools/lib/registries.mjs`, never from hand-written results.
- Feature icons come only from `icon` in `../bipe-shared/product/product.json`, drawn by `FeatureIcon` in `src/components/ui.tsx` (one tile for every status). Feature cards show no status; only the feature page shows it (`PlatformStatus`, figure caption), from `status` in `product.json`. Never write a status into a page or a card. One glyph per feature. A new glyph goes into `Icon` and `IconName`; rules in `../bipe/docs/design/identity.md` (Icons).
- Colours only from bipe-tokens CSS variables. Nunito only for the wordmark, titles and the big hero numbers on `/golpes-no-brasil/` (`.scam-value`). Chart labels, axes and values use `--ui` with tabular figures.
- pt-BR copy follows `../bipe/docs/design/linguagem.md` (ADR 0039).
- Rendered copy: no em or en dashes; run the humanizer rubric before it ships.
- Public pages never refer to MZ: no name, handle, initials or first-person founder voice, also not in sample data.
- Source links come from `source` in `../bipe-shared/product/distribution.json`. The site links a repo only when its `public` flag is true. Set the flag when the GitHub repo goes public (ADR 0024).
- Deep links into the code: add the file to `source.code` in `distribution.json` and name its id in `code` on a feature or technical part in `product.json`; pages render them with `CodeList` (`src/components/code.tsx`). Docs Markdown may link `github.com/bipe-chat/<repo>/blob/main/<path>` directly. `scripts/check-code-links.mjs` runs at the end of `pnpm build` and fails when a linked repo is not public or a path is not on `origin/main` of the sibling clone. A rename or move in an app repo breaks the site build until the link follows it.
- A feature is "No app de testes" only when it is in a TestFlight build.
- Headline test (issue #77, ADR 0032): `src/experiment.ts` holds the inline script that sets `#hero-title` before paint and the `sendBeacon` events. Arms live in `headlineTest` in `product.json`; h0 is `promise.pt.title`. Change a headline only there. Stop the test with `headlineTest.active: false`.
- The help form on `/ajuda/` (`src/sim/HelpForm.tsx`) posts to the `contact` form of the Bipe workspace on Starlings (`HELP_FORM_URL` in `src/config.ts`, bipe#273): each message becomes a private conversation there. All "talk to us" links go to `/ajuda/`; no page links a mail address.
- Waitlist forms post to `POST /v1/waitlist` (ADR 0025) through `src/sim/WaitlistForm.tsx`; the arm travels in `source`. `API_URL` is in `src/config.ts`.
- Every feature page shows an in-app mockup (a scene or a sim). A planned feature gets one too, labelled as a simulation with the planned status. The figure ids come from `figures` in `product.json` (required; `gen-product-doc.mjs` fails without it). Tentpole pages and `/empresas/` sections that describe a feature also show a figure.
- Sample people in simulations come only from the cast (`../bipe-shared/product/cast.json`, rules in `src/cast/STYLE.md`; the iOS store screenshots read the same file and the photos in `src/cast/photos/`). Phone scenes are data in `src/sim/scenes.ts`, rendered by `src/sim/ScenePhone.tsx`. Never hard-code a sample name or photo in a component. Never show a person's phone number in a simulation: Bipe hides numbers (ADR 0015); people appear by name and @handle. `/elenco/` (noindex) shows the cast and every scene. Skill: `.claude/skills/cast`.
- Cast photos are made with `node scripts/cast.mjs` (ChatGPT app's bundled Codex CLI, built-in `image_gen`, ChatGPT login, no API key). Full-size originals stay in `cast-originals/` (git-ignored).
- `/organizacoes/` (`/en/organisations/`) copy is `organisations` in `product.json` (ADR 0126). The page is for organisations that want to use Bipe; a partner uses the same form (kind `partner`), and the stewardship paragraph follows ADR 0067. No public page uses the Pix analogy (ADR 0071). Name no prospective partner, funder or institution until there is a signed agreement, and promise no seats, governance or equity. The form `src/sim/OrganisationForm.tsx` posts to the `organisations` form of the Bipe workspace on Starlings (`ORGANISATION_FORM_URL` in `src/config.ts`, bipe#273); each request becomes a lead there. `/parceiros/` and `/en/partners/` are redirects (`redirects` in `product.json`); redirect pages keep the `#fragment`.
- `/empresas/` copy is `business` in `product.json` and follows ADRs 0035 to 0037. Keep its "proposal" label until the business API ships. Change it together with the business messaging doc in Starlings Docs: https://docs-bipe.starlings.work/doc/strategy/business-messaging-companies-pay-users-do-not-11-october-2026

## Traps

- `registries.mjs` imports `node:fs`. `vite.config.ts` aliases it to `src/node-stub.ts` for the browser; `loadRegistries` runs only at build start to validate.
- @vitejs/plugin-react 6 needs Vite 8.
- PNG icons are rendered with macOS `qlmanage` in `scripts/icon.mjs`. On other systems they are skipped.
- Link-preview cards: every route gets a 1200x630 JPEG at `/og/<name>.jpg` (`scripts/lib/raster.mjs`, quality 82: a PNG of the gradients was 300 to 550 KB, over the WhatsApp preview limit of about 300 KB), rendered at build time by `scripts/og.mjs` (Satori and resvg, same on every machine). Text is the route's title and description; set `og` on a route to give the card its own title and line (example: `/organizacoes/`, from `organisations.card` in `product.json`). The footer shows only `bipe.chat`: no upper-case labels or pills on any rendered image. The privacy pages (`ogIllustration` in `src/entry-server.tsx`) show the Brazil network (`scripts/lib/brazil-network.mjs`) in place of the backdrop. The name comes from `ogImageName` in `src/routes.tsx`. The indexed cards of each language show on `/sobre/marca/`. A card uses only static text: never an invite code or a handle (crawlers fetch the URL with the code in it).
- OpenAI moderation blocks some cast photo outputs (`moderation_blocked`, `sexual`) on harmless prompts, for example a young woman "dressed to go out" in a changing-room mirror. Rewrite the `look` with plain, complete clothes and a home setting. Codex also sometimes answers DONE without calling `image_gen`; the script retries once.
- The link-preview cards and the store panels share one backdrop: `scripts/lib/backdrop.mjs` (texture, tones, the contrast check). `BRAND` there is the brand choice: mesh (no grain: noise made each card about 1.3 MB), the bubble mark, and `brandTone(i)` rotates açaí with pitanga, caju, jabuticaba and jenipapo by panel and by route. Do not draw a background in `og.mjs` or `panels.mjs`. The ramps come only from `../bipe-tokens` (`acai` in `tokens/theme-light.json`, the rest in `tokens/bipe-expressive.json`). The expressive ramps are for backgrounds only, never text, borders or trust states. CI checks out the bipe-tokens branch of the same name when it exists.
- Phone frames use continuous corners (`scripts/lib/squircle.mjs`, smoothing 0.6) with `screenRadius` from `../bipe-ios/appstore/devices.mjs`. The bezel is an SVG path; the capture is a Satori `img` with CSS `clipPath: path(...)`. An `<image>` inside an inline SVG does not render.
- resvg 2.6 panics (`geom.rs` unwrap) on a box shadow with a negative spread and on any box shadow inside a rotated element. `panels.mjs` draws the phone shadow as a blurred copy of the frame path, and the phones are upright.
- CSS entrance animations do not run in a hidden browser tab, so a screenshot of a hidden preview shows an empty phone.

## Before you push

- CI must stay green. `scripts/verify` runs what the required checks of the `main` ruleset run. Run it before every push; the pre-push hook runs it when this clone has `git config core.hooksPath .bipe-hooks` (set it once per clone; worktrees share it).
- A push with red local checks is not allowed. Never use `git push --no-verify`.
- If CI still fails on your pull request, fix it before you start other work. Never leave a red pull request at the end of a run.
